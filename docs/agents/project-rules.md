# Правила работы над Wi-Fi Mapper

## Цель и текущая граница
- Pet project для изучения Wi-Fi на Windows со встроенным адаптером ноутбука.
- Сейчас работаем строго над v0.1: TypeScript CLI и получение данных через netsh.
- Одна небольшая техническая задача за итерацию. Не переходить к истории измерений, Rust, UI, мобильному приложению или реконструкции без обсуждения с пользователем.
- Не предлагать покупку оборудования как обязательный шаг.

## Совместная работа
- Общаться на русском, объяснять не только как, но и почему.
- Предпочитать маленькие работающие изменения; не генерировать большой объём кода заранее.
- Предлагать альтернативы, когда есть существенный компромисс.
- Отделять подтверждённые возможности от гипотез и явно обозначать ограничения.

## Реализация
- TypeScript — основной язык. Rust возможен позднее для низкоуровневого сбора.
- Менеджер пакетов — только npm. Использовать `package-lock.json`; pnpm и Yarn не использовать, их lock-файлы не добавлять.
- Оформление JS/TS: четыре пробела, одинарные кавычки, точки с запятой, без пробелов внутри фигурных скобок импортов и объектов. Источник правил — `eslint.config.js`; автоисправление: `npm run lint:fix`.
- Python не делать обязательным без конкретной причины.
- Не добавлять зависимости и уровни абстракции без текущей необходимости.
- Отделять обращение к ОС от CLI; хранение и анализ выделять при появлении соответствующих задач.
- Учитывать будущую замену netsh на Native Wi-Fi API, не строить заранее универсальный framework.
- Учитывать локализацию и кодировку вывода netsh. Не считать его стабильным машинным форматом.
- Для новой и изменяемой логики добавлять юнит-тесты Vitest рядом с кодом (`*.test.ts`), включая успешные сценарии, ошибки и граничные случаи.
- При разработке использовать `npm test` (watch-режим). В юнит-тестах мокать обращение к ОС: не запускать реальный netsh, не зависеть от Wi-Fi, прав Windows и локальных измерений.

## Данные и эксперименты
- Использовать реальные данные; демонстрационные данные явно помечать.
- Не принимать процент качества сигнала за измеренный RSSI в dBm или CSI.
- Не трактовать RSSI как достоверную дистанцию или расположение стен.
- Не обещать восстановление геометрии по доступным данным без экспериментальных подтверждений.
- Не считать повторный вызов netsh гарантированно новым радиосканированием.
- При добавлении хранения сохранять исходные измерения для повторного анализа.
- Не коммитить реальные SSID, BSSID, MAC-адреса и другие локальные измерения.
- Не читать и не экспортировать пароли Wi-Fi: для текущей задачи они не нужны.

## Запуск текущей версии
- Node.js 24.12+; запуск: `node src/cli.ts --help`.
- Проверка типов: `npm run typecheck` после установки devDependencies.
- Установка зависимостей: `npm ci` при наличии lock-файла; после изменения зависимостей — `npm install`.
- Перед завершением изменений JS/TS выполнить `npm run lint`, `npm run typecheck` и `npm run test:run`.
- Команды: `drivers`, `interfaces`, `networks`.
- Только чтение через `netsh wlan show ...`; настройки ОС и разрешения автоматически не менять.
